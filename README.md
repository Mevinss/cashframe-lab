# Локальная проверка кассовых операций по видео

Работающий исследовательский прототип для кейса ForteBank: загрузка MOV, локальный анализ временных окон, асинхронный API, видео с хронологией, оригинальные JPEG-доказательства и ручная аннотация. Видео и кадры не отправляются облачным AI. Имя репозитория техническое; собственного бренда и логотипа нет.

**Модель недостаточно качественная для эксплуатации:** на 8 отложенных видео F1 0,67, все записи помечены положительными. Типы действий не подтверждены, автоматическое сопоставление нормативов выключено. Подробности — [эксперимент](docs/experiment-report.md) и [ограничения](docs/limitations.md). Технический запуск не означает готовность ко всем требованиям кейса.

## Проверенные результаты

- 42 исправных MOV, 40 уникальных источников. После группировки дублей: 21 положительный, 19 отрицательных. Фиксированное разбиение 24/8/8, seed 42.
- Замороженный DINOv2 ViT-S/14; реально обучен классификатор на 1 101 размеченном окне, из них 39 положительных. По 250 шагов Adam на конфигурацию, сохранены веса и журнал потерь. Дополнительный классификатор видео не улучшил validation и выключен.
- Самый длинный ролик, 142,53 секунды, обработан отдельным API-клиентом за **138,51 секунды**. Схема, временные отметки и JPEG проверены. Исходящая сеть в анализаторе блокируется; FFmpeg ограничен локальными протоколами.
- Проверки API/декодера используют синтетические видео. Браузерный сценарий проверен на ширинах 1280 и 390 px; синтетическая проверка интерфейса не оценивает модель.

## Запуск в Windows

Нужны Python 3.11 и FFmpeg/FFprobe в PATH. Интернет нужен только для установки и подготовки. Проверено на CPU с около 8 ГБ RAM. Один worker; фоновые приложения и свободная память влияют на скорость.

```powershell
cd D:\Datathon
.\scripts\setup.ps1
$env:PYTHONPATH='src'
$py='.\.venv\Scripts\python.exe'
& $py -m cashframe.cli prepare-encoder
& $py -m cashframe.cli audit --videos D:\open\open\videos --labels D:\open\open\open_labels.xlsx
& $py -m cashframe.cli features
& $py -m cashframe.cli train
.\scripts\start.ps1
```

На текущей машине веса и результаты уже подготовлены в `local/`. Для повторного запуска достаточно `scripts/start.ps1`. Без `.venv` скрипт использует существующий Python с установленными зависимостями.

Откройте [интерфейс](http://127.0.0.1:8000). Ключ для ввода находится в `local/api-key.txt`; при первом запуске создаётся случайный ключ. Он не встроен в JavaScript и не входит в Git. Альтернатива — переменная `CASHFRAME_API_KEY`. `.env` автоматически не читается.

Readiness: `GET /health/ready`, 503 без ключа или необходимых артефактов. Это техническая готовность конвейера, не подтверждение качества.

## API

Во всех рабочих API-запросах обязателен `X-API-Key`.

```powershell
$key=(Get-Content -Raw local\api-key.txt).Trim()
curl.exe -X POST http://127.0.0.1:8000/api/v1/analyze -H "X-API-Key: $key" -F "file=@path\video.mov"
curl.exe http://127.0.0.1:8000/api/v1/jobs/JOB_ID -H "X-API-Key: $key"
```

POST принимает multipart `file`, возвращает только `job_id`. GET: `processing`, `done`, `failed`. В done: `job_id`, `status`, `verdict` (`violation` / `no_violation`), `violations`. Событие содержит `type`, `timecode_sec`, `description`, `evidence_frames` с 1–3 JPEG (`timestamp_sec`, `image_base64`). Дополнительные данные — `/api/v1/jobs/{id}/review`, защищённое видео — `/api/v1/jobs/{id}/video`.

Тип текущего сигнала — «Визуальный сигнал — тип не подтверждён». Это не распознанная юридическая категория. Ошибки анализа возвращают failed без отрицательного вердикта. Занятость — 429, неверный ключ — 401, формат — 415, повреждённый контейнер — 422. Повреждение при полном декодировании приводит к failed. Файл до 100 МБ, длительность до 180 секунд, внутренняя граница 270 секунд с учётом загрузки. Остановленный сервис завершает дочерние процессы; прерванные задания становятся failed.

```powershell
& $py scripts\smoke_client.py path\video.mov
& $py -m unittest discover -s tests -v
```

## Данные и ручная разметка

- `local/dataset/`: приватный манифест, хеши, метки, разбиение.
- `local/encoder/`: веса, фиксированная ревизия энкодера, хеши. [Лицензии](docs/model-licenses.md).
- `local/features/`: кэш временных признаков, проверяемый по конфигурации.
- `local/experiment/`: обе модели, конфигурация, журнал и метрики. Первый эксперимент сохранён отдельно в `local/experiments/v1-window-only/`.
- `local/jobs/` и `local/jobs.sqlite`: загрузки, браузерные копии, ответы и приватные журналы. Срок хранения 24 часа, очистка при запуске и периодически, истёкшие задания недоступны через API.
- `local/annotations/`: подтверждённая разметка отдельно от предложений; сохраняется независимо от очистки заданий. Фиксируются SHA-256 источника, часть выборки и допустимость обучения. Внешние/жюрийные загрузки не становятся обучающими.

В карточке события раскройте «Уточнить и подтвердить событие»: задайте интервал, видимый факт, тип, проверяющего и предлагаемое основание. Это не меняет ответ модели и не запускает переобучение. Подтверждённые типы требуют отдельного обучения и оценки; классификатор типов пока не реализован. Сохраняйте разрешённые исходники в своём контуре и соблюдайте срок использования данных хакатона.

В реестре три проверенных пункта [акта НБРК № 231](https://adilet.zan.kz/rus/docs/V1900019680), [условия и ограничения](docs/rules.md). Автоматические связи выключены. Приоритеты редактируются в `config/priorities.json`; без подтверждённого основания приоритет не определён.

Очистка истёкших заданий вручную: `python scripts/cleanup.py --hours 24`. Исходные видео и Excel не затрагиваются. Удаление подтверждённых аннотаций после хакатона выполняет владелец данных.
