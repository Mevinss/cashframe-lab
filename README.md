# CashFrame — видеоаудит кассовых операций

CashFrame — исследовательский прототип для кейса ForteBank: загрузка видео, локальный анализ, асинхронный API, просмотр временных сигналов и исходных JPEG-кадров, ручная проверка и экспорт отчётов. Frontend и FastAPI работают на одной машине; инференс выполняется локально, без облачных AI API.

**Это инструмент помощи проверяющему, а не официальный сервис банка или автоматическое юридическое заключение.** Готовность API не означает подтверждённую точность модели или полное выполнение требований кейса.

## Возможности

- Обзор заданий, загрузка MOV/MP4, история результатов и состояние системы.
- Адаптивный интерфейс, светлая/тёмная темы и ru/kk/en.
- Хронология сигналов, оригинальные JPEG-кадры и просмотр видео.
- Ручные наблюдения, предварительный PDF-акт и Evidence Passport.
- Один общий ключ для API и браузерной сессии; восстановление входа после обновления страницы.
- Отдельный режим локальной разметки обучающих данных, выключенный по умолчанию.

Результат требует проверки человеком. Контекстный кадр не обязательно устанавливает момент действия; бинарный сигнал не определяет юридическую категорию. Автоматическое нормативное заключение без подтверждённых условий не заявляется. Подробнее: [соответствие кейсу](docs/forte-case-compliance.md), [статус классификации](docs/jury-access-and-classification.md), [нормативный аудит](docs/2026-10-18-rules-quality-audit.md).

## Запуск в Windows

### 1. Получить код

```powershell
git clone https://github.com/Mevinss/cashframe-lab.git
cd cashframe-lab
```

Для приватного репозитория нужен доступ участника. Клонирование не переносит модели, видео, окружение Python или API-ключ.

### 2. Подготовить окружение

Нужны **Python 3.11**, **FFmpeg и FFprobe**, для frontend-тестов — Node.js (в CI используется Node 22). Скрипт установки использует закреплённые зависимости и CPU PyTorch 2.6.0.

Если FFmpeg размещён в проекте, добавьте его только в PATH текущего PowerShell:

```powershell
$env:PATH = (Join-Path $PWD 'local/tools/ffmpeg/bin') + ';' + $env:PATH
ffmpeg -version
ffprobe -version
.\scripts\setup.ps1
```

Установка FFmpeg в эту папку не выполняется автоматически. Если он установлен в другом месте, укажите соответствующий каталог `bin`. Глобальный PATH менять необязательно.

Не заменяйте работающее окружение во время обслуживания запросов. Для отдельного окружения поддерживается:

```powershell
.\scripts\setup.ps1 -EnvironmentDirectory .venv-isolated
```

### 3. Разместить разрешённые модели

Для запуска уже обученной модели **не нужны исходный датасет, повторное обучение или скачивание весов при запросе**. Получите артефакты у ответственного участника по разрешённому приватному каналу, сохранив структуру:

```text
local/
  encoder/         # DINOv2: конфигурация и локальные веса
  experiment/      # исходный профиль; используется по умолчанию
  experiment-v2/   # отдельный профиль v2, если передан командой
```

Не смешивайте файлы разных профилей и не переименовывайте веса. Полный состав, происхождение и совместимость проверяются отдельно; `/health/ready` упражняет энкодер и классификатор. См. [настройку команды](docs/team-setup.md) и [лицензии моделей](docs/model-licenses.md).

### 4. Настроить личный ключ

Если `.env.local` ещё нет, скопируйте `.env.example` в `.env.local`. Не перезаписывайте существующий файл. Поддерживаются:

```dotenv
CASHFRAME_HOST=127.0.0.1
CASHFRAME_PORT=8000
CASHFRAME_API_KEY=
```

Пустой ключ означает создание/повторное использование случайного `local/api-key.txt`. Можно задать отдельный случайный ключ через `CASHFRAME_API_KEY`; реальные значения не публикуйте.

### 5. Запустить

Из корня проекта, в том же окне с настроенным PATH:

```powershell
.\scripts\start.ps1 -Bind 127.0.0.1 -Port 8000
```

Откройте **http://127.0.0.1:8000/**. Проверка готовности в другом окне:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health/ready
```

Ожидается HTTP 200 и `ready: true`. Ответ 503 означает, что runtime пока не готов: проверьте зависимости, FFmpeg/FFprobe, конфигурации и `local/readiness.log`.

Для выбора v2 и отдельного окружения укажите их явно:

```powershell
.\scripts\start.ps1 -Bind 127.0.0.1 -Port 8000 -ModelDirectory local/experiment-v2 -EnvironmentDirectory .venv-isolated
```

Это пример выбора, а не утверждение, что v2 или `.venv-isolated` установлены у каждого участника. `start.cmd` и запуск без `-ModelDirectory` используют `local/experiment`. Реальный профиль и статус классификатора проверяйте через защищённый `GET /api/v1/system`.

Остановка — **Ctrl+C** в терминале сервера. После перезапуска повторите настройку process PATH и команду запуска. Не запускайте второй экземпляр на занятом порту и не завершайте чужие процессы. Обновление backend через Git требует перезапуска сервера; push сам по себе его не обновляет.

## Ключ и браузерная сессия

Приоритет значений: аргументы запуска для host/port → переменные процесса → `.env.local` → `.env` → значения по умолчанию. Поддерживаются только три переменные из примера выше; значения читаются буквально, без выполнения shell-команд.

- Поддерживается **один глобальный API-ключ**, а не отдельные роли пользователей.
- Явный `CASHFRAME_API_KEY` имеет приоритет над `local/api-key.txt`; старый файл в этом случае не является действующим ключом.
- Launcher создаёт приватную инструкцию `local/jury-access.txt` с эффективным ключом. Не публикуйте её; ограничьте права доступа к файлам с секретами.
- Сайт использует восьмичасовую HttpOnly SameSite=Strict cookie. После перезапуска сервера нужно войти снова.
- Программный клиент передаёт ключ в `X-API-Key`; cookie для него необязательна. Ключ не должен попадать в URL, JavaScript, Git или журналы.

Для получения эффективного ключа в локальном Python-клиенте используйте тот же resolver, что и сервер, с `PYTHONPATH=src`. Не выводите значение:

```python
from cashframe.config import ROOT
from cashframe.launcher import load_environment, resolve_api_key

key = resolve_api_key(ROOT, load_environment(ROOT)["CASHFRAME_API_KEY"])
headers = {"X-API-Key": key}
```

## API и ограничения

| Метод и путь | Назначение |
|---|---|
| `GET /health/ready` | Техническая готовность, 200/503; ключ не требуется |
| `POST /api/v1/session` | Вход браузера по `X-API-Key` |
| `GET /api/v1/overview` | Счётчики и задания в пределах срока хранения |
| `GET /api/v1/system` | Профиль модели и статус компонентов |
| `POST /api/v1/analyze` | Multipart-поле `file`; ответ 202 с `job_id` |
| `GET /api/v1/jobs/{job_id}` | `processing`, `done` или `failed` |
| `GET /api/v1/jobs/{job_id}/review` | Контекст и измерения |
| `GET /api/v1/jobs/{job_id}/video` | Защищённое видео для просмотра |
| `GET /api/v1/jobs/{job_id}/report.pdf` | Предварительный PDF-акт |
| `GET /api/v1/jobs/{job_id}/passport` | Evidence Passport |
| `GET/POST /api/v1/jobs/{job_id}/annotations` | Ручные наблюдения |

Рабочие API и медиа защищены ключом либо браузерной сессией. PDF и паспорт поддерживают `?language=ru`, `kk` или `en`; это не официальные акты банка.

Для проверки протокола на разрешённом синтетическом MOV используйте существующий клиент:

```powershell
$env:PYTHONPATH = Join-Path $PWD 'src'
.\.venv\Scripts\python.exe scripts/smoke_client.py synthetic.mov --url http://127.0.0.1:8000
```

Перед запуском сверяйте параметры `--help` и эффективный ключ установки. Скрипт проверяет контракт, временные отметки и JPEG. Для конкурсного лимита отдельно измеряйте полное POST/upload/polling время; сетевые timeouts не равны строгому общему deadline. Подробнее: [чеклист API](docs/jury-checklist.md).

Завершённый JSON содержит `job_id`, `status`, `verdict` (`violation` / `no_violation`) и `violations`. У события есть `type`, `timecode_sec`, `description` и 1–3 `evidence_frames` с `timestamp_sec` и `image_base64`.

| Ограничение | Значение по умолчанию |
|---|---|
| Форматы | MOV / MP4 |
| Размер файла | 100 МиБ |
| Длительность | 180 секунд |
| Deadline приложения | 270 секунд, включая загрузку |
| Одновременный анализ | 1, без очереди |
| Хранение заданий | 24 часа; до 100 сохранённых заданий |
| Предел RSS анализа | 2048 МиБ |

Занятый worker возвращает **429** с `Retry-After: 10`; повторный POST не создавайте вслепую. После `done` слот может быть кратко занят подготовкой preview. Неверный ключ — 401, неверный формат — 415, некорректный запрос/контейнер — 422. Ошибка анализа даёт `failed`, а не отрицательный вердикт. Не увеличивайте число Uvicorn workers для обхода ограничений.

## Временный командный просмотр

Адрес настроенного командного экземпляра: **https://cashframe-vangogh.tailb541d9.ts.net/**. Он доступен только пока Windows-компьютер, CashFrame и foreground Tailscale Funnel работают; это не постоянное размещение и не обещание доступности для жюри. Посетителям Tailscale не требуется.

**Разрешены командный просмотр и синтетические тесты.** Реальные банковские и жюрийные видео требуют отдельного разрешения владельца данных на relay-транзит и локальное хранение. Модели не передаются посетителям. Не включайте публичный режим локальной разметки датасета.

Управление на уже настроенном хосте, только при разрешённом публичном доступе:

```powershell
# CashFrame должен быть готов на 127.0.0.1:8000.
& 'C:\Program Files\Tailscale\tailscale.exe' funnel --https=443 http://127.0.0.1:8000
# Foreground: остановка Ctrl+C. Проверка/удаление публичной конфигурации:
& 'C:\Program Files\Tailscale\tailscale.exe' funnel status
& 'C:\Program Files\Tailscale\tailscale.exe' funnel reset
```

Не создавайте второй Funnel на том же порту. Разрешение должно оставаться ограниченным Tailscale IPv4 конкретного хоста. Скрипты проекта не устанавливают Funnel и не включают unattended/автозапуск. После перезагрузки нужен ручной запуск; держите ноутбук на питании с открытой крышкой и подключённой сетью.

Funnel использует сторонние relay-серверы; пропускная способность и мобильный hotspot влияют на deadline. Personal ($0) предназначен для некоммерческого использования: применимость к банковскому Datathon необходимо уточнить отдельно. См. [официальный Funnel](https://tailscale.com/docs/features/tailscale-funnel), [условия плана](https://tailscale.com/pricing) и [размещение](docs/deployment.md).

## Измерения и качество

На командном Windows-хосте синтетический MOV **145 секунд, 1280×720, 30 FPS, 69,54 МиБ** завершился через публичный Funnel relay за **196,313 секунды**, включая POST и получение финального JSON. Передача тела заняла 59,297 секунды, POST roundtrip — 64,625 секунды. Это измерение исходного профиля `experiment` до последующего обновления backend, а не гарантия времени текущей версии.

Клиент работал на самом хосте с принудительным публичным relay-маршрутом. Внешнее открытие homepage подтверждено; независимый upload-бенчмарк с другого устройства/сети ещё необходим. Эти цифры не измеряют качество модели, не распространяются автоматически на v2, другие видео или нестабильную сеть. Полный внешний тест нужно повторять после изменения runtime/модели.

По исследовательским отчётам v2 дала 62,5% accuracy на восьми уже знакомых проверочных видео; это не независимая оценка нового ракурса. Принятого классификатора конкретных типов в описанном профиле нет; новые кандидаты не показали достаточного улучшения. Нельзя обещать 80–90% точности. [Результаты обучения](docs/2026-10-18-reviewed-training-results.md), [эксперимент v2](docs/model-v2-experiment.md).

## Проверки

Из корня проекта:

```powershell
$env:PYTHONPATH = Join-Path $PWD 'src'
$env:PATH = (Join-Path $PWD 'local/tools/ffmpeg/bin') + ';' + $env:PATH
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
node --test tests/frontend.test.cjs
git diff --check
```

Если выбрано другое окружение, замените `.venv` на его каталог. CI использует Linux/Python 3.11, FFmpeg, `requirements.lock` и Node 22. Синтетические тесты проверяют контракты и отказоустойчивость, а не точность на банковских сценах. Не запускайте тяжёлые проверки одновременно с обслуживанием оценки.

## Данные и модели

| Путь | Содержимое; не входит в Git |
|---|---|
| `.env.local` | Личная конфигурация и эффективный ключ |
| `local/api-key.txt`, `local/jury-access.txt` | Приватные ключ/инструкция доступа |
| `local/encoder`, `local/experiment*` | Веса и профили моделей |
| `local/dataset`, `local/features` | Приватный манифест, разметка и кэш признаков |
| `local/jobs`, `local/jobs.sqlite` | Загрузки, результаты, preview и журналы |
| `local/annotations` | Ручные наблюдения, хранящиеся отдельно от заданий |

Очистка заданий выполняется при запуске и периодически по сроку хранения. Аннотации имеют отдельный жизненный цикл; удаление и резервирование согласует владелец данных. Загрузки команды/жюри не становятся автоматически обучающими примерами. Не публикуйте `local/`, окружения Python, веса, датасеты, видео или секреты.

Подготовка данных, обучение, исследования действий и разметка не требуются для обычного запуска. Используйте отдельные инструкции: [ручная проверка данных](docs/2026-10-18-action-and-data-review.md), [обучение типов](docs/event-types.md), [изолированные эксперименты](docs/2026-10-18-quality-sprint-results.md). Не переобучайте и не заменяйте веса на работающем командном сервисе.
