# Offline Event Localization and Evidence Evaluation

Изолированный исследовательский инструмент на стандартной библиотеке Python.
Не импортирует приложение, не открывает видео, модели, `.env`, API или сеть;
читает только явно указанный JSON и выводит агрегированный JSON в stdout.
Не подключён к production и ничего не записывает сам.

## Запуск

Из корня репозитория, без установки дополнительных пакетов:

```bash
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python research/event_localization/evaluate.py \
  research/event_localization/synthetic_example.json \
  --iou-threshold 0.5 --point-tolerance-sec 0.5

PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m unittest discover \
  -s research/event_localization -p 'test_evaluate.py' -v
```

Оба порога обязательны и являются **экспериментальными настройками оценки**,
а не официальными требованиями ForteBank. Зафиксируйте их до независимой оценки;
не подбирайте по результатам тестовой выборки. Пример содержит только синтетику:
IoU = 1.75/2.25 ≈ 0.7778; localization precision/recall/F1 = 1;
MAE = 0.25 с; evidence inside fraction = 1/3; одно отрицательное видео без сигналов.

## Вход: sanitized JSON, schema_version = 1

Обязательные поля корня: `schema_version`, `videos` (список, может быть пустым).
Каждый элемент `videos` содержит только:

| Поле | Контракт |
| --- | --- |
| `duration_sec` | Конечное число > 0; секунды оригинального видео |
| `independent_review` | Строго `true`: организатор подтверждает независимую человеческую оценку |
| `events_complete` | Строго `true`: полный список целевых событий за всё видео, включая проверенное отсутствие |
| `video_positive` | Отдельное булево решение модели на уровне видео; не выводится из списка proposals |
| `ground_truth` | Список human-confirmed событий; пустой означает проверенное отрицательное видео |
| `predictions` | Список proposals, включая unresolved и дубликаты |

Ground truth: обязательны `confirmed: true`, `origin: "human"` и либо
`start_sec`/`end_sec` со строгим start < end, либо только `timecode_sec`.
Интервал может дополнительно иметь `timecode_sec` внутри себя — независимую
референсную точку для абсолютной ошибки. Середина интервала не подставляется.
Нулевой интервал недопустим: точку надо обозначать явно без границ.
Неподтверждённая, некорректная или повторённая ground truth отклоняет весь запуск.
Подтверждения здесь — декларации организатора, не автоматическая проверка
независимости, полноты, квалификации проверяющего или видимости действия.

Prediction: разрешены только `start_sec`, `end_sec`, `timecode_sec`,
`localization_status`, `evidence_frames` (список объектов только с `timestamp_sec`).
Для успеха обязательны конечный `timecode_sec` в пределах видео и статус
`model_proposal` либо `localized`. Отсутствующий/другой статус считается unresolved.
Если указана хотя бы одна граница, обе должны быть корректны, start < end,
а timecode должен лежать внутри. Некорректные временные поля не исправляются,
не обрезаются и остаются ошибочными predictions в знаменателе.
Для interval GT требуется валидный prediction-интервал; для point GT достаточно
валидного prediction-timecode. Все времена должны быть числами, не строками
и не bool. Границы видео и evidence-интервалов включены.

Имена временных полей и `model_proposal`/`unresolved` соответствуют существующим
read-only контрактам `events.py`, `pipeline.py`, `annotations.py`. Существующие
валидаторы не вызываются: они требуют текст наблюдения и другие приватные поля,
а annotation validator добавляет время сохранения. Это не повторная валидация
производственной разметки и не оценка типов.

Не передавайте raw review/result/annotations: whitelist отклоняет имена файлов,
идентификаторы источников, reviewer, observed_fact, description, type, кадры/base64
и любые неизвестные поля. Вход необходимо заранее подготовить локально из
разрешённых данных; инструмент не ищет и не читает их автоматически.

## Сопоставление и выход

Каждое видео сопоставляется отдельно. Ребро допустимо при IoU ≥ заданного порога
для interval GT или абсолютной ошибке точки ≤ tolerance для point GT.
Min-cost max-flow сначала максимизирует **число пар один к одному**, затем
максимизирует **суммарное качество** среди сопоставлений того же размера.
Для interval GT качество равно IoU; для point GT — `1 − |ошибка| / tolerance`.
При нулевом tolerance допустима только точная точка с качеством 1.
В смешанном наборе interval/point качества имеют одинаковый вес и диапазон [0,1];
это экспериментальная оценочная конвенция, не утверждение об эквивалентности
типов разметки или официальный банковский критерий. Даже ребро качества 0
на границе point tolerance предпочтительнее отсутствия пары: число пар первично.

Стоимость хранится как точная Fraction относительно десятичной записи `str(number)`
после JSON parsing (избыточная точность JSON float при parsing может теряться).
Это сохраняет ожидаемые границы вроде IoU 1/5 ≥ порога 0.2 без epsilon. Остаточные augmenting paths с
Bellman–Ford глобально оптимизируют вторую цель, а не жадно выбирают локальные пары.
Входные videos, GT и predictions канонически сортируются по всему очищенному JSON;
при равных оптимумах используются строгие обновления пути и фиксированный порядок
узлов/рёбер. Evidence участвует только в каноническом разрешении равных решений,
**не** в целевой функции. Полностью одинаковые predictions неразличимы;
их перестановка не меняет агрегаты. Перестановки списков videos/GT/predictions
не меняют результат. Перестановка списка evidence внутри prediction рассматривается
как изменение его канонического содержимого, поэтому для сравнения сохраняйте
порядок evidence; это не меняет основную цель, но может разрешить точное равенство.
В равных по основной цели решениях MAE/evidence могут различаться; выбранное
сопоставление воспроизводимо, но не оптимизирует эти побочные показатели.

Память O(P×G), поиск O(F×V×E), где F — число пар, V — число узлов,
E — число рёбер; Fraction добавляет стоимость точной арифметики. Инструмент
предназначен для небольших офлайн-наборов, не потоковой production-оценки.

Выход содержит только агрегаты и настройки, без отдельных пар и исходных timestamps:

- `video_detection`: TP/FP/FN/TN и precision/recall/F1 отдельно от локализации.
- `event_localization`: micro TP = число пар; FP = все proposals минус пары
  (включая unresolved/invalid); FN = вся GT минус пары; precision/recall/F1.
  Для смешанных наборов это явно комбинированная оценка interval-IoU и point-tolerance;
  `counts` отдельно показывает interval/point GT и matches. Для чистой interval-оценки
  используйте отдельно заранее выбранный набор видео с interval GT.
- `temporal_iou`: среднее **только по matched interval-парам** и число пар;
  это условная оценка, которую надо читать вместе с recall/FN. Point IoU не считается.
- `timestamp_error`: сумма абсолютных ошибок и MAE только по matched-парам
  с явной человеческой точкой, число референсов. Сырые индивидуальные ошибки
  не публикуются. Пропуски/далёкие point-предсказания видны через FN/FP, не в MAE.
- `unresolved_fraction`: число predictions без известного локализованного статуса /
  все predictions; `invalid_temporal_predictions` отдельно считает ошибки времени.
  Эти множества могут пересекаться.
- `evidence_timing`: доля submitted evidence timestamps внутри **сопоставленного**
  GT-интервала и доля matched interval-пар с хотя бы одним таким кадром.
  Evidence unmatched/negative/unresolved predictions не получает успеха;
  невалидные timestamps входят в знаменатель как ошибки. Для point-only видео
  и predictions, matched к point GT, interval correspondence не поддерживается,
  их кадры исключены и отдельно посчитаны в `evidence_point_unsupported`.
  Отсутствующие кадры считаются в `missing_evidence_predictions`, не подставляются;
  отсутствие evidence видно в interval coverage. Frame fraction не заменяет
  event coverage; повторённые timestamps считаются как поданные кадры.
- `negative_videos`: число независимо проверенных отрицательных видео,
  число false proposals и доля видео с proposals; не смешивать с video FP.
- `unsupported_metrics`: типы событий, визуальная релевантность, применимость нормы,
  point IoU, interval evidence для point GT и MAE без человеческого point-reference.

Знаменатель 0 → JSON `null`, а не фиктивные 0/100%. Ошибки структуры/ввода →
exit 2 и сообщение без значений или содержимого файла. Успех → exit 0.
Результат не подтверждает, что кадр показывает действие: timestamps доказывают
только временное соответствие. Тип, видимость и правовая оценка требуют отдельной
человеческой проверки; инструмент не делает заявлений о качестве реальных моделей.

## Дальнейшее применение

После разрешения владельца данных подготовьте локальный sanitized JSON в игнорируемом
`local/`, отдельно для независимых источников/камер и заранее выбранного split.
Сверьте соответствие оригинального времени, полноту целевого инвентаря и отсутствие
повторённых источников вне инструмента. Сопоставляйте review events с evidence
timestamps локально по контракту/идентификатору события, не вслепую по порядку;
не переносите payload кадров. Не превращайте существующие слабые points автоматически
в независимо подтверждённую полную GT. Неполный инвентарь нельзя называть negative:
без полной проверки инструмент намеренно отказывается считать PR/F1.
Текущая реализация не проверяет provenance и не оценивает межэкспертное согласие,
camera robustness, доверительные интервалы или семантическое качество.
Не меняйте приложение и не подключайте инструмент к обработчику запроса.
