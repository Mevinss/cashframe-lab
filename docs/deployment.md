# Запуск и размещение

Проверено локально на Windows/Python 3.11/CPU. Один процесс Uvicorn и один ограниченный worker. Несколько Uvicorn workers не включать: каждый получит собственный слот и модель, что превышает доступную память. Видео, веса, аннотации и секреты переносятся отдельно по разрешённому приватному каналу.

Подготовка и обучение — в README. Запуск: `scripts/start.ps1`. По умолчанию 127.0.0.1:8000, readiness `/health/ready`. Ключ хранится в исключённом из Git `local/api-key.txt` или переменной окружения. Подготовка весов и установка выполняются заранее; runtime не скачивает модели.

Командный запуск и перенос весов описаны в [инструкции для коллег](team-setup.md). Общие настройки находятся в `.env`, личные — в игнорируемом `.env.local`; затем применяются переменные окружения и явные параметры `-Bind`/`-Port`. Эти файлы читает launcher (`start.cmd`, `scripts/start.ps1` или `python -m cashframe.launcher`). Низкоуровневая команда `cashframe.cli serve` по-прежнему требует ключ в окружении и не загружает env-файлы.

Для внешнего доступа необходимы согласованный хост, HTTPS reverse proxy, ограничение размера запросов 101 МБ и закрытое хранение ключей. Хост и домен не предоставлены, публичное размещение не выполнено. Не публикуйте каталог local и датасет. Ключ для жюри передаётся отдельно; в frontend он не встроен.

Параметры запуска: `scripts/start.ps1 -Bind 127.0.0.1 -Port 8000`. Внешний bind применяют только после настройки защиты и доступа. API-медиа требует ключ, браузер использует авторизованные blob, ключа в URL нет.

Для переноса автономного сервиса подготовьте зависимости, FFmpeg, `local/encoder` и `local/experiment`, затем повторите отдельный smoke-клиент. Команду `prepare-encoder` в изолированном контуре без подготовленных материалов не запускать.

## Подготовленный профиль HTTPS для Linux

Шаблоны: `deploy/cashframe.service`, `deploy/nginx.conf`. Это конфигурации для проверки на целевом сервере, а не свидетельство работающего публичного адреса. Нужны разрешённый сервер с Python 3.11, FFmpeg/FFprobe, 4 ГБ RAM и запасом диска, домен, DNS и TLS-сертификат. Установите полный checkout в `/opt/cashframe`; установка wheel пока не является поддерживаемым способом размещения веб-ресурсов.

1. Создайте отдельного системного пользователя `cashframe`. Установите `.venv` через `python3.11 -m venv .venv`, затем `.venv/bin/python -m pip install -r requirements.lock` и `.venv/bin/python -m pip install torch==2.6.0 --index-url https://download.pytorch.org/whl/cpu --constraint requirements.lock`.
2. Приватно перенесите целиком `local/encoder` и выбранную папку классификатора. Для базового запуска это `local/experiment`. Не переносите чужой ключ, задания или аннотации. В `local/` разрешена запись только сервисному пользователю. Код и `.venv` доступны ему только для чтения.
3. Создайте `/etc/cashframe.env` с новым случайным `CASHFRAME_API_KEY`. Права `0600`, владелец root; systemd прочитает его до понижения прав. Не добавляйте секрет в Git, URL или access log.
4. Установите unit, выполните `systemd-analyze verify deploy/cashframe.service`, `systemctl daemon-reload`, затем запустите сервис. Readiness выполняет реальную загрузку DINOv2 и пробное вычисление; первый запрос может занять до 60 секунд. Ошибки находятся в `local/readiness.log`.
5. Замените домен и пути сертификата в Nginx, проверьте `nginx -t`, затем примените конфигурацию. Откройте извне только HTTPS/443 (80 нужен для редиректа/ACME), а порт 8000 оставьте локальным. Unit разрешает сервису только loopback-сеть; проверьте поддержку IP-фильтрации systemd на хосте. Nginx работает отдельно.
6. С другой машины проверьте HTTPS, отсутствие ключа → 401, readiness → 200, затем выполните `scripts/smoke_client.py` с разрешённым MOV и `--url https://ВАШ-ДОМЕН`. Ключ передайте в окружении клиента. Убедитесь, что получение PDF/паспорта/видео также требует ключа. Только после такого прогона отмечайте внешний доступ PASS.

## Ограничения и диагностика

Один Uvicorn process; очередь отсутствует, занятость возвращает 429. Ограничения по умолчанию: загрузка 100 МиБ, длительность 180 с, дедлайн задания 270 с, суммарная RSS дерева анализа 2048 МиБ, 100 сохранённых заданий, резерв свободного места 512 МиБ плюс размер загрузки, 12 событий и 36 JPEG на результат, 24 МиБ JPEG до base64, тело аннотации 16 КиБ. Превышение вычислительного лимита даёт failed, а не отрицательный вердикт. Дисковые лимиты проверяются перед приёмом; это защитные пороги приложения, не файловая квота ОС.

Готовый результат фиксируется до генерации превью. Превью ограничено 20 секундами и может стать недоступным без изменения статуса done; JPG, PDF и паспорт продолжают работать. В этом коротком интервале следующий анализ может получить 429.

Если положительный сигнал разбит более чем на 12 предложенных интервалов, возвращается один явно нелокализованный сигнал уровня видео с контекстными кадрами. Действия и их времена в этом случае не объявляются установленными. Ограничения времени и памяти продолжают приводить к failed при превышении.

Для задания сохраняются `worker.log`, `diagnostic.log`, `preview.log` в его локальной папке. Во внешнем API остаются обезличенные коды ошибок. Задания удаляются по сроку хранения 24 часа. Подтверждённые аннотации сохраняются отдельно как исследовательские материалы: организуйте их разрешённое хранение и резервирование. Мониторьте свободное место, RSS, частоту failed/429 и `/health/ready`; готовность сервиса не измеряет качество модели.

Перед заменой артефактов остановите сервис и сохраните прежнюю папку модели. Запустите тесты и реальный smoke после замены. Для отката выберите прежнюю модель через `--model-dir`. Не запускайте обучение, подготовку или скачивание модели в обработчике запроса.
