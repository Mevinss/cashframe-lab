# Передача сервиса участнику, который его развернёт

Этот checkout сам по себе не является публичным сервисом. Публичные HTTPS-адреса сайта и API предоставляет участник, отвечающий за размещение. Код может работать на его CPU-сервере; облачные AI для анализа не используются. Не публикуйте обучающие видео, кадры, описания, разметку и каталог `local/`.

## Что передать приватно

В Git находятся исходники и инструкции. Для автономного анализа дополнительно нужны FFmpeg/FFprobe, установленное Python-окружение и подготовленные артефакты:

```text
local/encoder/             # весь каталог: конфигурация, веса, исходники, лицензии
local/experiment-v2/       # весь выбранный каталог активной модели
```

Не ограничивайте v2 тремя файлами первоначального профиля: её видео-классификатор также использует `selected.npz` и `selection-frozen.json`. Передавайте выбранный каталог целиком без изменения содержимого. Не переносите отвергнутые экспериментальные головы вместо рабочей модели. Исходные видео, Excel, кэш признаков, аннотации, задания, базу заданий и прежний API-ключ для нового анализа переносить не требуется.

Установку зависимостей и загрузку весов завершите до отключения интернета. На целевой машине установите CPU PyTorch по [инструкции размещения](deployment.md). Запуск из полного checkout поддерживается; установка одного wheel не включает все веб-ресурсы.

## Запуск для жюри

На новой Windows-машине после подготовки окружения и артефактов:

```powershell
.\scripts\start.ps1 -ModelDirectory local/experiment-v2 -EnvironmentDirectory .venv-isolated
```

Если окружение создано обычным `setup.cmd`, используйте `-EnvironmentDirectory .venv`. Не указывайте `--dataset-review`: приватный интерфейс обучающей разметки должен быть выключен. Для Linux в подготовленном systemd unit задайте выбранный профиль явно:

```text
ExecStart=/opt/cashframe/.venv/bin/python -m cashframe.launcher --host 127.0.0.1 --port 8000 --model-dir local/experiment-v2
```

Оставьте внутренний порт доступным только reverse proxy. HTTPS-шаблоны и ограничения загрузки находятся в `deploy/` и [инструкции размещения](deployment.md). Один процесс сервера и один worker; при занятости API возвращает 429, клиент повторяет запрос после завершения текущего задания.

У каждой установки собственный случайный постоянный ключ. Для явно согласованного общего ключа задайте `CASHFRAME_API_KEY` приватно в окружении или `.env.local` на сервере и на проверяющей машине. Одна установка использует один и тот же эффективный ключ для входа на сайт и `X-API-Key`. Не помещайте ключ в Git, URL, HTML или JavaScript. При запуске локальная инструкция `local/jury-access.txt` содержит действующий ключ, но её loopback-адрес замените при передаче жюри фактическим публичным HTTPS-адресом. Перезапуск закрывает браузерную сессию, ключ сохраняется.

## Проверка перед передачей адреса

На машине сервера:

```powershell
$env:PYTHONPATH='src'
& .\.venv-isolated\Scripts\python.exe scripts\jury_preflight.py --base-url http://127.0.0.1:8000
```

Команда ничего не обучает и не загружает видео. Она читает существующий эффективный ключ без его создания или вывода, проверяет сайт, реальную readiness, отказ без ключа/с неверным ключом, вход через заголовок без cookie и отключение `/dataset-review`. Отчёт `local/jury-delivery.json` не содержит ключа, ответов API, кадров и человеческих описаний. Присутствие классификатора проверяется отдельно от технической готовности бинарной модели. `technical_preflight_passed` не означает выполнение всех требований или высокую точность.

После настройки адреса повторите команду **с другой машины**:

```powershell
& .\.venv-isolated\Scripts\python.exe scripts\jury_preflight.py --base-url https://ВАШ-РЕАЛЬНЫЙ-ДОМЕН
& .\.venv-isolated\Scripts\python.exe scripts\smoke_client.py ПУТЬ-К-РАЗРЕШЕННОМУ-ВИДЕО.mov --url https://ВАШ-РЕАЛЬНЫЙ-ДОМЕН
```

Ключ для smoke-клиента передайте через `CASHFRAME_API_KEY` или приватный `--key-file`; не через аргумент с самим секретом. Используйте разрешённый тестовый MOV или собственный синтетический ролик. Жюрийные видео не включайте в обучение, не публикуйте и не передавайте третьим лицам. Smoke проверяет схему, завершение менее чем за 300 секунд, таймкоды и декодирование JPEG; он не оценивает правильность нарушения или типа.

Preflight намеренно оставляет `public_reachability_verified: false` и `submission_complete: false`: запрос с самого сервера не доказывает внешний доступ, а короткие технические проверки не подтверждают качество событий. Приложите к передаче отдельно успешный результат внешнего MOV smoke, время обработки и дату проверки. Проверьте сайт и тот же ролик в браузере; для положительного результата откройте кадры, PDF и паспорт.

## Что отправить жюри

- Фактический публичный HTTPS-адрес сайта и базовый адрес API; localhost для удалённого жюри не подходит.
- Эффективный API-ключ по приватному каналу и способ передачи: заголовок `X-API-Key`.
- `POST /api/v1/analyze`, multipart-поле `file`; затем `GET /api/v1/jobs/{job_id}` до `done` или `failed`.
- [Архитектуру](architecture.md), [источники и ограничения применимости](rules.md), [фактический статус классов](jury-access-and-classification.md), [известные ограничения](limitations.md).
- Результат внешнего прогона, использованную версию кода и идентификатор выбранной модели. Готовность сервиса и качество модели сообщайте раздельно.

Наличие классификатора действий не подтверждает нормативную применимость. Для неизвестного типа, неустановленного момента или отсутствующего основания нельзя приписывать конкретное действие/правило. Такие случаи остаются пробелами качества и должны быть указаны в ограничениях, даже если JSON технически соответствует схеме.
