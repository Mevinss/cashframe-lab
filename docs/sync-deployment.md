# Одна версия локально и по HTTPS

HTTPS-адрес командной установки: **https://cashframe-vangogh.tailb541d9.ts.net/**. Доступность зависит от запущенных сервера и Tailscale Funnel. GitHub хранит исходники; `git push` сам по себе не перезапускает этот сервис и не переносит веса или ключ.

Веб-интерфейс уже отправляет запросы на `/api/v1/...` того же адреса, с которого открыт сайт. Отдельно прописывать `localhost` в интерфейсе не требуется. HTTPS-страница должна обслуживаться тем же сервером, который обрабатывает видео.

## Обновление на компьютере, где работает HTTPS

1. Сохраните собственные изменения. В каталоге проекта выполните `git status`, затем `git switch main` и `git pull --ff-only origin main`. При конфликте или незакоммиченных изменениях сначала сохраните их; не применяйте `reset --hard`.
2. Остановите прежний процесс сервиса обычным способом. Сохраните выбранные веса и ключ в приватной папке `local`; Git их не переносит. При изменении зависимостей обновите окружение по [инструкции установки](team-setup.md).
3. Запустите актуальный backend с текущим профилем: `scripts/start.ps1 -ModelDirectory local/experiment-v2 -EnvironmentDirectory .venv-isolated`. При другом имени окружения укажите его явно. Для HTTPS не включайте `--dataset-review`.
4. Сохраните уже настроенный Funnel на этом компьютере. Не создавайте второй туннель. Если Funnel был остановлен, используйте существующую процедуру из [README](../README.md#временный-командный-просмотр).
5. Проверьте готовность и общий ключ на целевом экземпляре. Обновите браузер с перезагрузкой ресурсов, если он сохранил прежние файлы.

## Проверка совпадения

Из подготовленного окружения проекта:

```powershell
$env:PYTHONPATH='src'
.venv-isolated/Scripts/python.exe scripts/check_deployment_sync.py --target https://cashframe-vangogh.tailb541d9.ts.net/
```

Проверка читает только публичные HTML/CSS/JS, готовность и схему API. В отчёт `local/deployment-parity.json` попадают статусы и SHA-256 файлов; видео, задания и разметка не читаются. При различии хотя бы одного ресурса команда завершится с ненулевым кодом. Сетевой сбой также означает, что совпадение не подтверждено.

Для проверки одного согласованного ключа на обоих указанных адресах добавьте `--check-auth`. Ключ берётся из текущего приватного окружения и не выводится. Ключ передаётся только на `/api/v1/system` двух явно указанных адресов; переходы на другие адреса отключены.

Дополнительно выполните `scripts/jury_preflight.py --base-url https://cashframe-vangogh.tailb541d9.ts.net/` для проверки авторизации и недоступности учебной разметки. Различие ключей установок решается приватной настройкой `CASHFRAME_API_KEY` на сервере и его перезапуском; ключ не встраивается в JavaScript.

## Приватная памятка с ключом

Чтобы получить Markdown для жюри, выполните на установке с согласованным ключом:

```powershell
.venv-isolated/Scripts/python.exe scripts/export_jury_access.py --base-url https://cashframe-vangogh.tailb541d9.ts.net/
```

Файл создаётся строго в игнорируемой папке `local/jury-access.md`. Скрипт читает существующий ключ и проверяет его одним GET-запросом к `/api/v1/system`; ключ не создаётся и не меняется. Если сервер ответил 401, в памятке будет явно написано, что ключ не принят. Сетевой сбой или иной ответ сохраняет статус «не подтверждён». Такой файл нельзя выдавать за подтверждение работающего доступа. Для другого существующего ключа укажите `--key-file` с приватным файлом. В Git отправляется только инструкция, без самого ключа.

Для отдельной локальной памятки можно явно указать `--base-url http://127.0.0.1:8000/`. В этом случае проверяется только локальный адрес, а доступ по HTTPS остаётся неподтверждённым. HTTP разрешён только для loopback.

Совпадение ресурсов и названия профиля ещё не доказывает совпадение весов или результата анализа. Для полного совпадения приватно перенесите `local/encoder` и весь `local/experiment-v2`, проверьте SHA-256 артефактов на обоих компьютерах и выполните согласованный тест обработки. Файлы профилей нельзя смешивать.
