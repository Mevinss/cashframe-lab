# Локальный эксперимент с распознаванием последовательностей

## Аудит действующего анализатора

`features.py` выбирает кадры примерно с частотой 4 кадра/с, уменьшает до 168×168, нормализует ImageNet mean/std и получает 384-мерный вектор из замороженной DINOv2 ViT-S/14. Это признаки изображения, а не координаты объектов или готовые категории действий. `learning.py` строит перекрывающиеся окна радиусом 1 с с шагом 0,5 с и считает среднее, стандартное отклонение и среднюю абсолютную скорость изменения векторов. Скорость зависит от соседства кадров, но направление и порядок действий в окне теряются. Линейный классификатор выдаёт бинарный балл окна. Балл видео — максимум по окнам; отдельная video-bag модель в установленном профиле выключена.

Исходные метки организаторов: бинарное «нарушение / без нарушения» и точка времени у положительных записей. При обучении берутся все окна отрицательного видео и только окна не дальше 0,75 с от точки положительного видео. Остальные окна положительного видео не назначаются отрицательными. Подтверждённых названий типов действий в текущей локальной копии нет. `events.py` объединяет окна выше порога, выбирает пик как таймкод и назначает общий тип «визуальный сигнал». Если сигнал не локализуется, используется отметка 0 с явным предупреждением. `pipeline.py` выбирает кадры до, около и после пика, затем привязывает таймкод к реальному исходному кадру. Описание сообщает о сходстве с размеченными фрагментами, не утверждает конкретный факт или нарушение правила. Отдельный классификатор типов включается только при наличии прошедшего проверку человеческого артефакта; сейчас его нет. Правила из `config/rules.json` проверены как тексты, но автоматическое сопоставление выключено.

Текущее разбиение в `local/experiment/config.json`: 24 / 8 / 8 групп train / validation / test. `data.py` группирует точные SHA-256 дубликаты до разбиения. Порог и регуляризация исходной модели выбирались по validation, не по test во время исходного обучения. Однако восемь test-видео уже просматривались в предыдущих экспериментах; их нельзя снова называть новым независимым слепым тестом. Визуально похожие, но не идентичные файлы и независимость ракурсов не подтверждены.

## Замороженный baseline

Перед изменением эксперимента вся исходная папка `local/experiment` скопирована в игнорируемую Git папку `local/baselines/v1-original`. Она содержит `config.json`, `trained.npz`, `baseline.npz`, `report.json`, `training-log.json`. Установленный профиль: `selected_variant=trained`, 1101 обучающих окон, из них 39 положительных; video-bag выключен. Исходная папка и основной сервис не менялись. Скрипт сравнения проверяет тождество split и конфигурации энкодера.

Локальный `report.json` содержит для текущего профиля на validation 0 истинно отрицательных, 4 ложные тревоги, 0 пропусков и 4 истинно положительных видео. Поле `test_evaluated=false`: в этой восстановленной копии нет сохранённой test-оценки baseline. Контрольные суммы пяти сохранённых файлов записаны в `local/baselines/v1-original.sha256.json`.

## Альтернатива

`sequence_candidate.py` строит упорядоченные последовательности из 16 DINO-векторов в перекрывающихся 4-секундных окнах с шагом 1 с по всей записи. Между фактическими временными метками применяется интерполяция. `sequence_training.py` содержит небольшой TCN: проекция 384→32, две временные depthwise-свёртки и классификатор. Он выбран вместо GRU из-за малого числа независимых положительных видео и меньшего числа обучаемых параметров. Это гипотеза для проверки, не заявленное улучшение.

После предсказания соседние окна одной категории объединяются. Время события — центр окна с наибольшим баллом; для доказательств выбираются ближайшие *исходные* кадры к началу, пику и концу. Описание строится из подтверждённой командой категории. Ссылка на правило появляется только при явно заданном соответствии категории с проверенным правилом, у которого разрешено автоматическое сопоставление. Сейчас ни одной такой связи нет; эксперимент оставляет правило неопределённым. Инференс не читает таблицу организаторов.

Если выделенный сигнал покрывает почти всю запись, слишком дробится или не имеет различимого пика, локализация помечается как неразрешённая. Тогда таймкод 0 является только технической отметкой контекста, а не заявленным временем действия; оценка ошибки локализации такой результат не засчитывает.

В таблице разметки пустые `start_sec`, `end_sec` и `event_type` заполняет человек. `organizer_point_sec` — подсказка для поиска, не готовый интервал. `coverage_complete=yes` допустимо только после полного просмотра записи: лишь тогда участки вне подтверждённых событий могут стать отрицательными окнами. При неполном просмотре они остаются без метки. Для каждого положительного train/validation-видео нужен хотя бы один подтверждённый интервал; для каждого отрицательного — подтверждённый полный просмотр. `event_type` можно оставить пустым, тогда обучается только бинарный детектор событий. Для обучения конкретных типов нужны как минимум два человеческих типа, по 3 независимые train-группы и 2 validation-группы на тип. Разметка прямоугольников не нужна.

Шаблон столбцов: [event-annotation-template.csv](event-annotation-template.csv). Для рабочей таблицы из восстановленного манифеста:

```powershell
$env:PYTHONPATH = 'src'
.\.venv\Scripts\python.exe scripts\sequence_experiment.py review-table
```

Команда сохраняет `local/annotations/event-review.csv` с локальными именами исходных файлов и точками организаторов. Исходный `.xlsx` и видео не изменяются. Повторный вызов не перезаписывает заполненную таблицу. Если подтверждено несколько событий в видео, добавьте строку с тем же `source_sha256` и своим интервалом. Для неполной разметки `coverage_complete=no`; неизвестные значения оставляйте пустыми.

## Протокол сравнения

После возврата исходных видео и локального DINO-кэша выполните аудит данных штатными командами из README. Сохраните прежний `split.json`, а не стройте новое разбиение после просмотра результатов. При наличии известных визуальных дубликатов заполните `duplicate_group` в манифесте и убедитесь, что их группы не пересекают части split. Обучение читает только train и validation признаки/подтверждённые интервалы. Среднее и разброс признаков оцениваются только по train; эпоха выбирается по validation, затем порог видео фиксируется по validation. Тестовые аннотации могут быть внесены после обучения; они не влияют на frozen-кандидат.

```powershell
$env:PYTHONPATH = 'src'
.\.venv\Scripts\python.exe scripts\sequence_experiment.py train
.\.venv\Scripts\python.exe scripts\sequence_experiment.py evaluate
.\.venv\Scripts\python.exe scripts\sequence_experiment.py benchmark --report local/experiments/sequence-tcn/timing.json
```

`evaluate` записывает агрегаты по одинаковым test-группам: пропуски и ложные тревоги на уровне видео, ложные события только на полностью просмотренных отрицательных видео, macro F1 типов при наличии меток и ошибку таймкода до ближайшего подтверждённого интервала. Для baseline событие с неразрешённой локализацией не получает искусственную ошибку от отметки 0. Ошибка таймкода из кэша — приближённая: уточнение интервала и привязка к JPEG в действующем сервисе требуют оценки по исходным видео. `benchmark` отдельно измеряет полный локальный проход по исходным test-видео: декодирование, DINO, модель, кадры. Оба отчёта создаются один раз и не перезаписываются. Текущий test-набор ранее просматривался; для решения о переключении сервиса нужен также новый независимый набор, желательно с иным ракурсом.

## Текущий статус

В этой рабочей копии есть энкодер и обе обученные старые модели, но отсутствуют `local/source`, `local/dataset`, `local/features`, исходная таблица меток и человеческие интервалы. Поэтому TCN не обучен, сравнение ошибок и полного времени не выполнено, улучшение не подтверждено. Основной API, интерфейс и выбранная модель остаются прежними. Кадры, признаки и описания не передаются наружу.
