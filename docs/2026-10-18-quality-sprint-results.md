# Проверка качества и подготовка разметки — 18 октября 2026

Этот документ отделяет выполненную инженерную работу от качества, которое пока не достигнуто. Исходный план: [двухчасовой спринт](superpowers/plans/2026-10-18-quality-80-roadmap.md). Действующий профиль остаётся `local/experiment-v2`.

После завершения пользовательской разметки выполнен отдельный этап обучения TCN. Он также не улучшил качество; его данные, исправление критерия остановки и полные результаты описаны в [следующем отчёте](2026-10-18-reviewed-training-results.md). Остальная часть этого документа фиксирует состояние первого этапа.

## Проверка моделей

Контроль сохранён в игнорируемой папке `local/baselines/v2-before-quality-sprint`, контрольные суммы — `snapshot-sha256.json`. Активные веса не заменялись. X-48 и его точный дубликат X-5 относятся к одной отрицательной train-группе; это диагностический пример, а не новый независимый тест.

| Модель | Validation N | TN / FP / FN / TP | Accuracy / balanced accuracy | Recall | Решение |
|---|---:|---|---:|---:|---|
| Активный v2 | 8 | 1 / 3 / 0 / 4 | 62,5% / 62,5% | 100% | Контроль |
| Mean/linear, ridge 100 | 8 | 1 / 3 / 0 / 4 | 62,5% / 62,5% | 100% | Не устанавливать |
| Activity-only, linear ridge 100 | 8 | 1 / 3 / 0 / 4 | 62,5% / 62,5% | 100% | Не устанавливать |
| RBF по исходным положительным точкам и отрицательным видео | 8 | 0 / 4 / 0 / 4 | 50% / 50% | 100% | Не устанавливать |

Первый вариант воспроизводит конфигурацию, уже встречавшуюся в v4; он не является новой архитектурой. Activity-only исключает статическое среднее изображения, но улучшение не подтвердилось. Последний вариант использует слабую исходную разметку: ближайшее окно к положительной точке и окна видео с исходной отрицательной меткой. Это не человеческие интервалы и не разметка типов. Неизвестные участки положительного видео исключены из его обучения. Для этого варианта test не открывался.

Порог действующего v2 не удалось улучшить на validation при сохранении recall. Подгонки под X-48, чтения меток при инференсе, автоматической замены модели или выдачи train-качества за обобщение нет. Восемь старых test-видео остаются знакомой регрессией: accuracy 62,5%, precision 57,1%, recall 100%, specificity 25%. Новый независимый ракурс не проверен.

Локальные числовые отчёты: `local/audit/quality-80-baseline.json`, `quality-80-binary.json`, `quality-80-activity-binary.json`, `quality-80-point-kernel.json`. Числа времени и RSS в экспериментальных runner — замеры, а не гарантия пикового потребления процесса.

## Рабочая подготовка разметки

Добавлен отдельный opt-in экран `/dataset-review`: исходные train/validation-видео, точки организаторов, реальные начало и конец, автор, описание, тип, видимость и отдельное подтверждение полного просмотра. Test-видео не выдаются. Доступ к данным, видео и сохранению защищён `X-API-Key`; по умолчанию инструмент выключен.

Запуск на этой установке:

```powershell
$env:PYTHONPATH='src'
.\.venv-isolated\Scripts\python.exe -m cashframe.launcher --host 127.0.0.1 --port 8000 --model-dir local/experiment-v2 --dataset-review
```

Ключ остаётся в `local/api-key.txt` либо заданном окружении. Для публичной установки жюри флаг разметки не включать. Секреты, исходники видео, признаки, аннотации и веса в Git не добавлять.

Мастер данных — `local/dataset/events-review.csv`, покрытие — `local/dataset/review-coverage.csv`. Отдельные интервалы, даже подтверждённые, не означают полного просмотра. Наблюдение без подтверждения целевого события сохраняется как `draft` и не поступает в обучение детектора нарушений. Шаблон описания не является результатом распознавания. Человек должен сверить его с видео; неизвестные условия нельзя дописывать как факт.

В редакторе есть семь готовых шаблонов на ru/kk/en: передача сумки, работа с ящиком, возвращение к рабочему месту и четыре предлагаемые категории возможных нарушений. Выбор заполняет тип и готовый текст, сохраняет ручные правки и снимает подтверждение целевого события. Старое правило очищается при смене шаблона, ручной смене типа или снятии подтверждения. Эти шаблоны не анализируют пиксели и не заменяют просмотр. При неверном имени проверяющего поле подсвечивается с понятным сообщением; введённая разметка сохраняется в форме.

История сохранений хранится в `local/annotations/dataset-revisions`. Исходные точки сохраняются, человеческие записи получают собственные стабильные ID. При импорте CSV-черновика или подтверждённой строки с исходным ID её наблюдение переносится под отдельный ID, исходная точка восстанавливается. Последующее подтверждение не меняет ID человеческого наблюдения. Конкурирующие API-записи сериализуются блокировкой, устаревшая версия отклоняется; изменения файлов проверяются повторно перед записью. Не редактировать CSV внешним приложением одновременно с веб-редактором: внешний редактор не участвует в блокировке. Проверяется SHA-256 видео перед его выдачей для разметки.

Версионируемый bridge переводит сохранённую таблицу и отдельное покрытие в существующую схему TCN. Есть provenance и SHA-256 входов/выхода; изменение входов отменяет экспорт. Неполные и неопределённые интервалы не становятся отрицательным фоном. При полном просмотре с неэкспортируемым интервалом эффективное отрицательное покрытие понижается до неизвестного.

```powershell
$env:PYTHONPATH='src'
.\.venv-isolated\Scripts\python.exe scripts\sequence_review_bridge.py convert --table local/dataset/events-review.csv --coverage local/dataset/review-coverage.csv --output local/dataset/sequence-reviewed-v1.csv
```

Выходные файлы создаются новой версией, не перезаписываются. До запуска обучения нужно проверить сводку разметки. Типовому trainer требуются хотя бы два подтверждённых типа, каждый на трёх независимых train- и двух validation-источниках. Это технический минимум, не доказательство 80% точности. TCN дополнительно требует реальные положительные интервалы и явное покрытие отрицательных видео. Прямоугольники для этого пути не нужны.

## Нормативы и типы

[Официальный источник РК](https://adilet.zan.kz/rus/docs/V1900019680) перепроверен; [нормативный отчёт](2026-10-18-rules-quality-audit.md) содержит условия и ограничения. `config/action-types.json` описывает нейтральные действия. `config/violation-types.json` отдельно содержит четыре предлагаемые категории возможных нарушений с названиями и условиями на ru/kk/en. Это не официальный перечень и не обученные веса. К каждому типу нельзя автоматически присоединять нарушение только по бинарной метке.

Общий validator требует полный проверенный источник, название документа, условия и HTTPS-ссылку; пункт остаётся необязательным по последнему FAQ. Он применяется в сопоставлении, compliance и PDF. Строка `"false"` не включает автоматическое сопоставление. Неполный источник не становится подтверждённым. Все автоматические правовые сопоставления текущей модели выключены.

Для инкассаторских сумок действует отдельная процедура: передача сумки и отсутствие немедленного вскрытия сами по себе не нарушение. Нужно различать вид операции и условия применения источника. Общий пересчёт, открытие ящика, передача бумаги и выход из кадра также не превращаются в нарушение без контекста.

## Реальная проверка продукта

Через работающий HTTP API заново обработаны случаи, выбранные по исходной метке и длительности, без отбора по ответу модели:

| Случай | Длительность видео | Полное время | Результат против исходной метки | Техническая проверка |
|---|---:|---:|---|---|
| Короткий положительный train | 14,33 с | 13,95 с | Совпадает | Строгая схема, 3 JPEG, PDF, паспорт, хэши |
| Короткий отрицательный train | 15,57 с | 15,44 с | Совпадает | Строгая схема, пустые события, PDF, паспорт, хэши |
| Самый длинный train/validation | 142,53 с | 66,50 с | Ложная тревога | Строгая схема, 3 JPEG, PDF, паспорт, хэши |

У всех трёх анализаторов исходящая сеть заблокирована, browser preview доступен. Это проверка интеграции и измерение скорости, не независимая accuracy. У положительного и длинного случая локализация осталась `unresolved`: контекстные кадры не доказывают момент события. Полный машинный отчёт — `local/verification/quality-80-sprint/results.json`.

Новый экран проверяется отдельно на синтетических цветных видео: сохранение, стабильные ID, отказ тестовым источникам, блокировка формы на время Save, ru/kk/en, светлая/тёмная темы, ширины 1366 и 390 px. Проверены сохранение ручного описания и сброс устаревшей нормы при смене шаблона/класса. Банковские кадры в браузерную автоматизацию и внешние AI не передаются. Синтетические тесты не подтверждают качество модели.

Финальные программные проверки: 231 Python-тест и 29 frontend-тестов проходят. После обновления сервиса `/health/ready` возвращает HTTP 200. Числовая сводка, контроль неизменности активных весов, решения по трём кандидатам и снимок количества человеческих подтверждений сохранены в `local/audit/quality-80-final.json` с временем создания. Последующая ручная разметка меняет данные, но не переобучает модель автоматически.

## Статус обязательных требований

| Требование | Фактический статус |
|---|---|
| Веб-загрузка → анализ → статус → результат | Работает локально, повторно проверено |
| Два заданных вердикта и строгий API с ключом | Реализованы; ошибка обработки не становится отрицательным вердиктом |
| Надёжное обнаружение | Не достигнуто: ложные тревоги остаются |
| Тип каждого возможного нарушения | Подготовлены каталог, разметка и trainer; требуется подтверждённый набор и проверка обученной модели |
| Таймкод каждого события | Ненадёжно; unresolved нельзя засчитывать за корректную локализацию |
| Кадры-доказательства | Выдаются настоящие JPEG; релевантность событиям ещё требует проверки |
| Фактическое объяснение | Человеческие наблюдения сохраняются; автоматического надёжного описания кассового действия пока нет |
| Норматив для каждого события | Проверенный реестр есть; автоматическая применимость для неизвестного типа не установлена |
| Локальность и запрет распознавания лиц | Сохраняются; лицевые эмбеддинги, идентификация и облачный видеоанализ не добавлены |
| Новый ракурс | Нет независимой оценки; аугментация старых кадров её не заменяет |
| До пяти минут | Три измеренных ролика прошли; это не гарантия всех нагрузок и файлов |
| Доступ жюри по внешнему URL | В этом спринте публичная публикация не выполнялась |

Работа не даёт основания объявить 80% точности или полное соответствие кейсу. Следующий источник улучшения — подтверждённые целевые интервалы/типы и новые независимые сцены, а не дальнейший перебор на прежних восьми validation-видео. Внешние датасеты и более глубокий энкодер в этом спринте не добавлялись.
