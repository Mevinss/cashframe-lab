# Реализация и проверка CashFrame Lab

Дата: 17.10.2026. Ветка: `fix/datathon-reliability`. Коммиты и push не выполнялись. Существовавшее до работы изменение `.env` сохранено без редактирования. Веса, исходники видео, признаки, ключи и подробные журналы находятся в игнорируемом `local/`.

Сервис действительно запускается и выполняет DINOv2-инференс через HTTP. Основные дефекты надёжности устранены. Полная готовность к кейсу не достигнута: качество детекции остаётся слабым, нет подтверждённых типов действий и независимой проверки на другом ракурсе, публичный URL не предоставлен.

Исходный Starlette 0.48.0 подпадал под [GHSA-7f5h-v6xp-fcq8](https://github.com/Kludex/starlette/security/advisories/GHSA-7f5h-v6xp-fcq8). Проверен регрессионный Range-запрос.

## Изменённое поведение

Неконечные коэффициенты, пороги, признаки, промежуточные переполнения и оценки теперь вызывают явную ошибку. Повреждённая модель не может превратиться в успешный отрицательный вердикт. Readiness выполняет отдельную проверку загрузки и вычисления, кэширует успешный результат и перепроверяет изменённые артефакты. Диагностика сохраняется локально.

Аннотации ограничены 16 КиБ; неизвестные поля отвергаются. Серверные поля происхождения не принимаются на доверии и вычисляются заново. Сравнение API-ключей работает с байтами и возвращает 401 для неверного Unicode-заголовка.

Окна инференса используют радиус и шаг из конфигурации; паспорт фиксирует именно эти значения и действительный порог событий. JPEG извлекаются одним проходом FFmpeg по исходным индексам кадров. Сохраняются исходные PTS, размеры и содержимое JPEG; добавлена проверка декодирования изображений.

Положительное решение классификатора видео больше не превращается в искусственный argmax-таймкод при неинформативной последовательности оценок. Плоский, слишком широкий, подпороговый или чрезмерно раздробленный сигнал получает `localization_status=unresolved`. API сохраняет положительный сигнал уровня видео; отметка 0 и кадры начала/середины/конца явно обозначены как контекст, а не установленное действие. Это честная неопределённость, а не решение задачи точной локализации.

Завершённый результат сохраняется до генерации превью. Отказ или таймаут превью не меняет done на failed, не скрывает JPEG и не изменяет ревизию отчёта. В интерфейсе результат появляется до загрузки медиа; GET-запросы имеют таймауты и повторные попытки, POST не дублируется автоматически, получение существующего задания можно возобновить. Исправлены перенос сотых долей секунды и старое выделение временного интервала.

Введены ограничения дерева процессов по RSS, числа сохранённых заданий, свободного места, числа JPEG и их суммарного размера. Дедлайн анализа остаётся 270 с. Внешний ответ содержит безопасный код ошибки, локальные `worker.log`, `diagnostic.log`, `preview.log` сохраняют причину. Умершие worker threads удаляются из списка.

## Реальные MOV через API

Сценарии выбраны заранее по метке и длительности: самый короткий положительный и отрицательный train-источник и самый длинный train/validation-источник. Все три оказались в train. Эти проверки подтверждают интеграцию, а не независимую точность. Времена измерены от POST до done, без последующего скачивания отчётов.

| Исходник | Истинная метка | Baseline: результат / время | v2: результат / время |
|---|---|---|---|
| 14,333 с | положительный | violation / 20,046 с | violation / 20,094 с |
| 15,567 с | отрицательный | no_violation / 19,527 с | no_violation / 19,527 с |
| 142,533 с | отрицательный | violation, ошибка / 108,184 с | violation, ошибка / 108,184 с |

Во всех шести итоговых запусках соблюдена точная схема jury API. У каждого положительного результата по три валидных исходных JPEG. Превью в итоге вернуло 200, PDF содержит 2–3 страницы, паспорт и контрольные суммы корректны. Все зарегистрированные анализаторы работали с блокировкой исходящих Python-соединений и локальными протоколами FFmpeg. Максимальная записанная RSS анализа — 345,4 МБ; это измерение процесса, не доказательство пика всего дерева процессов.

Отдельно создан новый синтетический MOV длительностью 3 с и 30 FPS, отсутствующий в обучении. Он прошёл тот же настоящий v2 API за 12,204 с, вернул done и валидные JPEG; записанная RSS — 418,7 МБ. Модель выдала violation на тестовом изображении. Этот сценарий проверяет приём нового файла и выполнение конвейера; банковская разметка для него отсутствует, и он не используется как доказательство точности или устойчивости к новому ракурсу. Результат: `local/verification/unseen-api-smoke.json`.

На самом длинном файле первый прогон обнаружил воспроизводимый сбой нового ограничения 12 интервалов. Он исправлен: раздробленный положительный сигнал теперь сохраняется с явно неподтверждённой локализацией и ограниченным набором контекстных кадров. Повторный прогон того же файла прошёл. Первоначальный failed и его журналы сохранены локально. Полученные длинные отрицательные ролики по-прежнему являются ложными срабатываниями модели.

## Сравнение моделей без настройки по test

| Модель | Train OOF accuracy | Validation accuracy | TN / FP / FN / TP на validation | Решение |
|---|---:|---:|---|---|
| DINOv2 normal-reference baseline | не оценивалась | 50% | 0 / 4 / 0 / 4 | сохранён |
| Восстановленный v1 window classifier | не оценивалась | 50% | 0 / 4 / 0 / 4 | сохранён |
| Воспроизведённый v2, mean + linear ridge 10 | 70,83% | 62,5% | 1 / 3 / 0 / 4 | отдельный рабочий исследовательский профиль |
| Новый v3, temporal pyramid + linear ridge 0,1 | 79,17% | 50% | 0 / 4 / 0 / 4 | отклонён |

V2 воспроизведён за 6,137 с. V3 сравнил 45 заранее записанных комбинаций: mean, mean/std, quantiles, временную пирамиду и динамические разности; linear/RBF ridge. Архитектура выбиралась по четырём source-disjoint train-folds, порог — только на validation. Время v3 — 9,741 с.

Для v3 проверялся консервативный порог с specificity ≥ 0,75 и recall ≥ 0,5. Такого порога не нашлось; кандидат не включён в приложение. Улучшение относительно прежнего v2 **не доказано**. Рост обучающего OOF не перенёсся на validation. Optical Flow не добавлен без положительного экспериментального основания. Старый test не переоценивался и не использовался для выбора; его признаки были только восстановлены штатным извлечением. Validation также уже использовался раньше, поэтому даже его лучшие числа не являются независимой оценкой.

## Типы, нормативы и дополнительные функции

Подтверждённых меток типов в рабочей копии нет. `train_types.py` вернул `not_trained`, артефакт не создан. Для имеющегося классификатора нужны как минимум два конкретных типа, по три независимых train-источника и два validation-источника на каждый, человеческое подтверждение и ясная видимость; затем должен пройти порог качества. Бинарные метки и point-timecodes этого не заменяют.

Существующий локальный реестр трёх норм Казахстана сохранён; новые нормы и цитаты не придумывались. В этой сессии юридическая редакция повторно не верифицировалась. Автоматическое сопоставление остаётся выключенным. Человек отдельно указывает наблюдаемый факт, видимость и применимость нормы; невыданный невидимый документ, финансовый баланс и намерение автоматически не выводятся.

Выбор кадров Before–Event–After теперь учитывает границы предложенного интервала. При неопределённой локализации интерфейс и PDF показывают «Контекст видео». Добавлены реальный график изменений яркости между соседними выборками, переход к времени по графику и предупреждения о тёмных/светлых/малодетальных выборках. График не является вероятностью нарушения, включает влияние освещения/камеры и не является Optical Flow. Техническое качество не подтверждает видимость действия. Workspace Matrix и Reverse Audit не реализованы: валидированных объектов, зон и состояний событий для них нет.

## Запуск и повторение проверок

Окружение и модели на этой машине уже подготовлены. Для запуска v2:

```powershell
cd C:\Users\nurda\Downloads\Datathon\cashframe-lab
.\scripts\start.ps1 -Bind 127.0.0.1 -Port 8000 -ModelDirectory local/experiment-v2
```

Интерфейс: `http://127.0.0.1:8000`. Используйте настроенный `CASHFRAME_API_KEY`; если настройка пуста, launcher использует `local/api-key.txt`. Для baseline опустите `-ModelDirectory`. Не запускайте второй сервер на том же порту.

```powershell
$env:PYTHONPATH='src'
$env:PYTHONIOENCODING='utf-8'
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
node --test tests/frontend.test.cjs
.\.venv\Scripts\python.exe scripts/acceptance_local.py --output local/verification/acceptance-repeat
```

Для нового эксперимента задайте свежую папку `--output`; замороженные результаты не перезаписываются. Условия HTTPS, конфигурации systemd/Nginx, лимиты и проверка с другой машины описаны в [deployment.md](deployment.md). Linux-шаблоны подготовлены, но на целевом хосте не выполнялись.
