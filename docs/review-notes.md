# Проверка реализации

Независимая проверка исходного кода нашла четыре существенных дефекта; каждый воспроизведён и исправлен:

- Зависшая загрузка: дедлайн теперь действует при чтении multipart, незавершённые временные файлы закрываются, слот освобождается. Проверено асинхронным клиентом с задержкой тела.
- Остановка сервиса: worker отслеживает дочерние процессы, завершает их деревья и помечает задание failed. Проверено настоящим синтетическим дочерним процессом, который ранее переживал shutdown.
- Подтверждение разметки: required-поля должны быть непустыми строками, confirmed — Boolean; null/списки/объекты не принимаются как подтверждение.
- Срок хранения: периодическая очистка действует без перезапуска; истёкшие результаты закрыты для API. Подтверждённые аннотации сохраняются отдельно от временных заданий.

После исправлений: 35 автоматических проверок, ноль ошибок, включая запуск с ResourceWarning как ошибкой. Проверен полный установочный скрипт. Итоговая повторная API-проверка новой версии на коротком исходнике: 44,1 секунды, корректные схема, JPEG и таймкоды. Отдельный клиент и анализатор — разные процессы на этой машине; проверка с другой физической машины/внешнего URL не выполнена.

Независимая проверка интерфейса выявила три проблемы: отображение неизвестного покрытия, потерю клавиатурного фокуса и потерю/перенос черновика разметки. Все три исправлены и оценены повторным reviewer как resolved. Итоговый disposition: ship **только для этих трёх исправлений**. Это не утверждение готовности модели. Браузерные проверки выполнялись только на синтетическом видео; приватные кадры не передавались инструментам просмотра.

Принятые технические решения:

1. Работа в выбранной пользователем новой папке на отдельной ветке, без дополнительного worktree. Это не защищает от параллельного редактирования той же папки.
2. Стандартный DINOv2 ViT-S/14 выбран по явной Apache 2.0 для кода и весов, вместо ImageNet-весов с непроверенными условиями. CPU-время измерено; другие машины требуют повторного замера.
3. Длительность VFR определяется также по концам presentation-пакетов: метаданные контейнера могут недооценивать конец. Цена — дополнительное лёгкое чтение пакетов.
4. Маленький классификатор обучается явным Adam с журналом потерь; большая модель с нуля не обучается. Низкое качество не скрывается.
5. Подтверждённый пользователем точный интерфейс и стек перенесены в PRODUCT/DESIGN без повторного интервью. Не выбраны новые бренд, логотип или рекламная композиция.
6. Видеоклассификатор агрегатов проверен только по validation и отвергнут из-за отсутствия улучшения. Test уже просмотрен: следующему исследованию нужен свежий внешний holdout.
7. Существующая основная ветка нового личного репозитория содержит только созданные здесь материалы; код публикуется в неё после проверки. Чужие изменения не перезаписываются.

Области, на которые review не даёт гарантии: полезность all-positive модели, применимость норм к неподтверждённым действиям, человеческая релевантность доказательств, новый ракурс, распределение задержек на неизвестных данных, внешний HTTPS и общесистемная сетевая изоляция. Эти ограничения сохраняются открытыми, подробнее в limitations.md. Критических дефектов в рассмотренном диапазоне исходного кода reviewer не обнаружил; существенные замечания устранены. Отдельных minor findings reviewer не оставил.
