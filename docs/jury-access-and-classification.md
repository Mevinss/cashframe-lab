# Доступ жюри и статус классификации

## Один ключ для сайта и API

Эффективный ключ текущей установки используется и в интерфейсе, и в заголовке `X-API-Key`. При запуске создаётся приватная инструкция `local/jury-access.txt` с адресом и этим ключом. Если ключ задан в `.env.local` или окружении, инструкция содержит именно его; иначе применяется постоянный `local/api-key.txt`. Эти файлы не входят в Git.

В интерфейсе ключ вводится один раз: сервер выдаёт сессию на восемь часов в HttpOnly SameSite=Strict cookie. После перезагрузки страницы вход восстанавливается. Секрет не помещается в исходники, HTML, URL или localStorage. Для автоматической проверки жюри по-прежнему доступен `X-API-Key`; cookie не обязательна. При перезапуске сервера браузерную сессию нужно открыть снова, ключ остаётся прежним.

API кейса: `POST /api/v1/analyze`, multipart-поле `file`; ответ 202 с `job_id`. Состояние и результат — `GET /api/v1/jobs/{job_id}`. Дополнительный защищённый `GET /api/v1/system` показывает техническую готовность и `type_classifier`: `absent`, `inactive`, `active` или `invalid`, число классов, версию и SHA артефакта. Техническая готовность бинарного анализа не означает готовность типизации.

## Что с классификатором

Обработка уже вызывает локальный классификатор для выделенного интервала. При принятом артефакте его тип попадает в результат, а происхождение и SHA — в данные проверки. Оценка центроидной головы обозначена `uncalibrated_margin`: это не процент вероятности нарушения. Для неопределённого интервала или неуверенного класса система сохраняет отказ от типизации.

**В активной v2 принятого `types.npz` пока нет. Классификатор нарушений не готов.** Последние CPU-кандидаты не улучшили обнаружение, а экспериментальная голова действий ошиблась во всех пяти проверочных интервалах. Пороги не снижены, неудачная голова не активирована. Восемь файлов действующей бинарной модели сохранены. Числа и артефакты приведены в [отчёте](2026-10-18-reviewed-training-results.md).

## Три приоритетных категории для следующего обучения

Это выбранный объём разметки, а не утверждение, что перечисленные классы уже распознаются.

| ID | Категория-кандидат | Что необходимо установить по видео |
|---|---|---|
| `leave_before_service_end` | Уход до окончания обслуживания | Уход именно с рабочего места при продолжающемся обслуживании; обычный уход после окончания исключается |
| `cash_receipt_count_without_client_presence` | Приём/пересчёт без клиента | Клиентская операция приёма, видимые наличные и достаточный обзор зоны клиента; внутренний пересчёт исключается |
| `prior_cash_outside_designated_storage` | Ранее принятые деньги вне предусмотренного хранения | Отличимость ранее принятых денег от текущей операции и видимое место их оставления |

Проверенные источники и ограничения применимости описаны в [нормативном аудите](2026-10-18-rules-quality-audit.md). Обычное действие или положительная метка всего видео не доказывают эти условия. Автоматический подбор нормы остаётся выключенным до подтверждения категории и её условий.

Для каждого выбранного типа нужны подтверждённые интервалы и похожие обычные операции. Минимум текущего trainer — три независимых train- и два validation-источника на тип, затем macro-F1, coverage и precision/recall каждого типа не ниже 0,8. Это технический минимум запуска, не гарантия обобщения. Новых независимых видео с другого угла пока нет; преобразования старых кадров такую проверку не заменяют.

Следующая архитектура: замороженные визуальные признаки + объектные области и временная голова действий; отдельный слой проверенных правил с условиями применимости. Модель и порог фиксируются перед проверкой новых сцен. Замена v2 допускается только при улучшении обнаружения без увеличения пропусков и после проверки классов, таймкодов, кадров и полного API.

## Обязательный результат: фактический статус

| Требование | Статус |
|---|---|
| Загрузка, запуск, статус и результат через сайт/API | Реализованы |
| Два заданных текста вердикта | Реализованы; корректность решения ограничена качеством модели |
| Анализ визуальных событий | Есть бинарный поиск сигналов; надёжность недостаточна |
| Конкретный тип каждого события | Не достигнуто: принятого классификатора нет |
| Таймкод каждого события | Частично: для нелокализованного сигнала показывается контекст, а не установленный момент |
| Кадры-доказательства | Выдаются; контекстные кадры не доказывают момент или действие |
| Объяснение наблюдаемого действия | Не достигнуто полноценно: общий текст срабатывания не заменяет наблюдаемого факта |
| Норматив для каждого события | Не достигнуто автоматически; нужны категория и применимые условия |

Полное выполнение кейса и качество 80% сейчас не заявляются.
