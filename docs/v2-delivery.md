# Доработка видеоаудита и предварительный PDF

Версия приложения 0.2.0 добавляет локальный предварительный PDF-акт, паспорт доказательств, расширенную человеческую разметку, обучение типов и отдельный экспериментальный классификатор видео. До полного выполнения кейса остаются качество распознавания, подтверждённая типология, независимая проверка другого ракурса и внешнее размещение.

## Предварительный акт

PDF создаётся по сохранённому завершённому заданию без повторного анализа видео и без сети. В нём номер/даты UTC, технические параметры, исходный вердикт модели, события и интервалы, фактические JPEG «До — Событие — После», отдельные наблюдения человека, применимые проверенные нормативы, версии/хеши, ограничения и место для заключения/подписи проверяющего. Подписи и банковские согласования не имитируются.

ReportLab и Unicode-шрифт DejaVu Sans работают локально; лицензия шрифта сохранена рядом с ним. Пример на синтетических фигурах:

```powershell
$env:PYTHONPATH='src'
& .\.venv\Scripts\python.exe scripts\example_report.py
```

Результат: `local/previews/preliminary-audit.pdf` и `passport.json`. Это синтетический документ для проверки оформления; он не доказывает качество модели и не содержит банковских кадров.

Кнопки скачивания доступны и при отсутствии найденных событий. Авторизация сохраняется. Для каждого набора результата/разметки/реестра создаётся отдельная неизменяемая редакция; повторный запрос возвращает её же. Новая разметка создаёт следующую редакцию, не изменяя ответ модели и прежний PDF. Очистка задания удаляет его отчёты. Контрольные суммы скачивания проверяются; повреждённый кэш не выдаётся за исходный документ.

Основной проход анализирует всё видео по выборке 4 кадр/с. Дополнительное уточнение 8 кадр/с выполняется только при достаточном остатке бюджета; иначе сохраняются первоначальные интервалы, а пропуск уточнения явно отражается в ограничениях и паспорте. Браузерная копия совместимого H264/yuv420p переупаковывается без изменения видеопотока, с началом первой видеорамки в нуле; для других форматов остаётся перекодирование. Проверяются переменная частота и видео, начинающееся позже аудио. Кадры-доказательства всегда извлекаются из исходника.

## Evidence Passport

Канонический JSON (UTF-8, сортировка ключей, без лишних пробелов) содержит SHA-256 исходного видео, фактических включённых JPEG, модели локализации, энкодера, конфигурации и Python-исходников приложения. Для экспериментального видеоклассификатора и модели типов добавляются собственные хеши. Указывается эффективный порог, который действительно использовался при анализе. Код идентифицируется хешем канонического словаря относительных `.py`-путей и их SHA-256; это идентификатор содержимого, а не подпись доверенного издателя.

Версии фиксируются во время анализа. Старым заданиям не приписываются установленные сегодня модели: неизвестные сведения явно отмечены. Идентификатор паспорта вычисляется из манифеста до добавления идентификатора; SHA-256 полного файла указан в PDF и HTTP-заголовке. Проверка целостности не подтверждает юридическую истинность наблюдения. Паспорт не содержит API-ключей или абсолютных внутренних путей.

## Типы и нормативы

Человек указывает интервал, конкретное действие, тип, видимость и автора. Черновики хранятся отдельно. Общие метки «нарушение»/«неизвестно» не становятся подтверждёнными типами. Подтверждение применимости нормы требует полностью видимых условий и отдельной отметки проверяющего; сам выбор пункта остаётся предложением. Реестр берётся только из локального `config/rules.json`; во время генерации документа интернет-поиск не выполняется.

Обучение типов использует только подтверждённые видимые действия, доверенные хеши исходников и сохранённое разбиение. Тестовые/внешние/жюрийные источники исключаются до чтения их признаков. Проверки на синтетических признаках доказывают работу механизма, но не распознавание реальных категорий. Без человеческих примеров модель типов не устанавливается. Подробности в [event-types.md](event-types.md).

| Требование | Состояние |

| Загрузка MOV, статус, результат в интерфейсе | Реализовано локально |
| Точная схема двухэтапного API, X-API-Key | Сохранена; отчёты добавлены отдельными маршрутами |
| Полностью локальный AI после подготовки весов | Сохранён; генерация PDF также не использует сеть |
| Обработка до 5 минут | Повторные замеры текущей версии записаны в acceptance-v2.json; гарантий для неизвестной нагрузки нет |
| Таймкоды и кадры | Фактические JPEG и PTS связаны хешами; релевантность действий ещё требует человеческой оценки |
| Надёжное обнаружение | Не достигнуто: v2-кандидат 62,5% на прежнем тесте, три ложных срабатывания из четырёх отрицательных видео |
| Конкретные типы и объяснения | Есть разметка, обучение/валидация/отказ от неизвестного; реальных подтверждённых категорий пока нет |
| Нормативное обоснование | Проверенный локальный реестр и подтверждение человеком в PDF; автоматическое распознавание применимости не заявляется |
| Другой ракурс | Независимых размеченных записей нет, качество не оценено |
| PDF | Реализован предварительный документ и паспорт, включая отрицательный результат |
| Внешний адрес для жюри | Не предоставлен; localhost не заменяет публичный URL |

Оценка 85–90% не достигнута. Сравнение на уже просмотренном тесте является исследовательским; новый независимый набор необходим для окончательного принятия модели. Увеличение модели не заменяет отсутствующую разметку действий и другого ракурса. На текущем CPU-компьютере с 7,7 ГБ RAM во время интеграционной проверки оставалось около 0,84 ГБ доступной памяти; дообучение всего энкодера не запускалось. Вместо него выполнен воспроизводимый подбор 27 небольших моделей по сохранённым признакам с разделением источников.

## Проверка текущей версии

85 автоматических тестов прошли с ResourceWarning как ошибкой. Независимый просмотр кода нашёл и помог исправить фактический порог в паспорте, неодинаковую проверку неизвестных типов и смещение времени при раннем аудио в MOV. Проверены обычная и переменная частота, идентичность видеопотока при переупаковке и идентичность JPEG при повторном использовании временных отметок.

Отдельный API-клиент на этой машине проверил три исходных ролика: 21,881 с для отрицательного примера, 37,961 с для Х‑11, 139,000 с для самого длинного ролика 142,533 с. Схема, JPEG, PDF и паспорт проверены для каждого. Это проверки времени и интеграции, а не дополнительная независимая оценка точности. Промежуточный нагруженный прогон до повторного использования временных отметок завершился failed по дедлайну 270 с; он сохранён в отчёте, а не заменён отрицательным вердиктом. Другой успешный промежуточный прогон занимал 263,5 с. Фоновая нагрузка и доступная память существенно меняют задержку; три успешных замера не гарантируют время для любого файла.

SHA-256 исходных 42 файлов повторно проверены и не изменились. Синтетический PDF проверен визуально, включая кириллицу и казахские символы. В браузере проверены скачивание и человеческая разметка на ширинах 1280 и 390 px. Подробные агрегаты находятся в acceptance-v2.json; приватные результаты и веса остаются в local/.
